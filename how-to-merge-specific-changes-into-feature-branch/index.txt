1d:Tb71,<h2>How to merge specific changes into feature branch</h2>
<p>Have you ever found yourself working on a feature branch that is a few commits behind <code>main</code>, and you realize you need an update from <code>main</code>—but <strong>only</strong> for one specific file?</p>
<p>Worse yet, you’ve already made your own changes to that same file, so a simple copy-paste or full overwrite will destroy your progress.</p>
<p>Instead of merging the entire <code>main</code> branch or manually copying lines of code, Git has a built-in superpower for this exact scenario: <strong>Interactive Patch Checkout</strong>.</p>
<p>Here is a simple, step-by-step guide to using <code>git checkout -p</code> to selectively pull code line-by-line.</p>
<h3>The Core Command</h3>
<pre><code class="hljs language-bash">git checkout -p origin/main -- path/to/file.js
</code></pre>
<h3>What does this mean?</h3>
<p><code>--path/to/file.js</code>: Restricts the operation strictly to this file.</p>
<p><code>-p</code> (or <code>--patch</code>): Tells Git to break the differences between your branch and main into small, digestible blocks of code called "hunks". Git will ask you one by one whether you want to pull each hunk into your branch.</p>
<h4>Step 1: Fetch the latest changes from Main</h4>
<p>Before doing anything, make sure your local machine knows about the absolute latest updates on your remote repository.</p>
<pre><code class="hljs language-bash">git fetch origin main
</code></pre>
<h4>Step 2: Make sure you are on your feature branch</h4>
<p>Ensure you are working inside the branch where you want the changes to land.</p>
<pre><code class="hljs language-bash">git checkout your-feature-branch
</code></pre>
<h4>Step 3: Run the interactive checkout command</h4>
<p>Target the exact file you want to update from main.</p>
<pre><code class="hljs language-bash">git checkout -p origin/main -- path/to/file.js
</code></pre>
<h4>Step 4: Review and choose your "Hunks"</h4>
<p>Once you press Enter, Git will display the first block of differences. Green lines are additions from <code>main</code>, and red lines are deletions.</p>
<p>At the bottom of the terminal, you will see a prompt like this:</p>
<blockquote>
<p>Stage this hunk? [y, n, q, a, d, j, J, g, /, s, e, ?]:</p>
</blockquote>
<p>Don't be intimidated by all the letters! You only need to know a few:</p>
<ul>
<li>
<p><code>y</code> (yes): Pull this specific change from <code>main</code> into your file.</p>
</li>
<li>
<p><code>n</code> (no): Skip this change and keep your branch's version exactly as it is.</p>
</li>
<li>
<p><code>s</code> (split): If the block of code is too big, this splits it into even smaller pieces.</p>
</li>
<li>
<p><code>q</code> (quit): Stop the process entirely. Any hunks you already said y to will be saved.</p>
</li>
</ul>
